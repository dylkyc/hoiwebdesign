## 1. combat_width 与 combat_support_width

### 1.1 游戏本体玩家可见措辞（逐字）
`localisation/english/terrain_l_english.yml`：
```

TERRAIN_COMBAT_WIDTH_COMB: "Combat width: $VALUE|0Y$ (Additional attacks: $ADD|0Y$)"
TERRAIN_ADDITIONAL_WIDTH: "Combat width per additional direction: $VALUE|=0Y$"
```
→ **combat_support_width 的官方显示名就是 "Combat width per additional direction"**。

`localisation/english/combat_l_english.yml`：
```
COMBAT_COMBAT_WIDTH_DESC: "§HCombat Width§!\n Decides how many divisions on each side will be able to join the fight. How much width a division takes up depends on how it has been designed. By attacking from multiple directions you can increase the available total width."
COMBAT_RESERVES: "Reserves are divisions that haven't been able to join the combat yet.\n\nIf there is sufficient combat width then every hour of battle a single division from the reserves will be selected to try and join.\n\nDivisions with comparatively high reinforcement rate in the reserves are more likely to be selected."
COMREIC_TOO_MUCH_WIDTH: "Is too wide a unit, so would give a large penalty."
```

### 1.2 数值表（一手：`common/terrain/00_terrain.txt`）

| 地形 | combat_width | combat_support_width |
|---|---|---|
| urban 城市 | 80 | 40 |
| plains 平原 | 70 | 35 |
| hills 丘陵 | 70 | 35 |
| desert 沙漠 | 70 | 35 |
| forest 森林 | 60 | 30 |
| jungle 丛林 | 60 | 30 |
| mountain 山地 | 50 | 25 |
| marsh 沼泽 | 50 | 25 |

- support 恒为 combat_width 的 1/2。
- **不存在 40 这一档**；用户记忆的「80/70/60/50/40」应是把 urban 的 80 与其 support 40 混在了一起。
- 文件内保留了旧系统的百分比写法（已注释）：
```
forest:   #combat_width = -0.20   combat_width = 60
hills:    #combat_width = -0.33   combat_width = 70
mountain: #combat_width = -0.66   combat_width = 50
```

### 1.3 结论
两者都是「**整场战斗的总宽度**」，不是「每个方向的宽度」。combat_width 是单方向时的总宽度基线；combat_support_width 是每多一个进攻方向追加的宽度。

Wiki 原文片段（[Land units diff](https://hoi4.paradoxwikis.com/index.php?title=Land_units&diff=104726&oldid=26371#4)）：
> "If attacking divisions come from more than one province, then width is added to the battlefield for each province"

## 2. 超宽惩罚（over width penalty）

### 2.1 defines 原文（一手，行 1107-1108）
```lua
COMBAT_OVER_WIDTH_PENALTY = -1,      -- over combat width penalty per %.
COMBAT_OVER_WIDTH_PENALTY_MAX = -0.33,  -- over combat width max (when you cant join no more).
```

Wiki Defines 页同两行（搜索索引逐字片段）：
> "COMBAT_OVER_WIDTH_PENALTY | -1 | over combat width penalty per %" — [Defines diff](https://hoi4.paradoxwikis.com/index.php?title=Defines&diff=65801&oldid=60894#26)
> "COMBAT_OVER_WIDTH_PENALTY_MAX | -0.33 | over combat width max (when you cant join no more)" — [Defines diff](https://hoi4.paradoxwikis.com/index.php?title=Defines&diff=98329&oldid=36432#11)

关键：官方注释把 -33% 与「**when you cant join no more**」直接绑定。

### 2.2 公式（分段线性，分母是 Battle Width 而非 Total Width）
```
若 Total <= Battle:  penalty = 0
若 Total >  Battle:  penalty = max(-0.33, -1 × (Total - Battle) / Battle)
```
即 penalty% = -(Total - Battle)/Battle × 100%，每超宽 1% 扣 1%。

**第三方逐字（gamerempire.net，https://gamerempire.net/hearts-of-iron-4-what-is-combat-width/）**：
> "Here is the exact equation used to calculate the Exceeding Combat Width debuff in HOI4: Total Width stands for the number of Combat Width your divisions get for the battle. Battle Width stands for the Combat Width of the province."
> "Let's say you are fighting in a province with 105 Combat Width (Battle Width) where you have 118 Combat Width on your side (Total Width). This means that you will get a -12.3% ((118-105)/105*100) Exceeding Combat Width debuff to your Attack and Defense for all the divisions present in the battle."
> "This can also change based on how many directions the province is attacked from (+half of the normal Combat Width per attack direction)."

**第三方逐字（jpn.itlibra.com/article/24091，日文）**：
> 計算式 | −100% ×（合計幅 − 戦闘幅）÷ 戦闘幅 ；上限 | −33% で頭打ち
> 戦闘幅 80 の都市戦 : 合計 106 幅まで入る（この時ペナルティ −32.5%）
> 戦闘幅 70 の平野で 20 幅の師団 : 3 個で 60（ペナルティなし）、4 個で 80 → −14.3%、5 個目は予備待機

两个独立来源都以 **Battle Width（允许宽度）为分母** → **用户猜想 (a) 正确；(b) 1/(1-0.33) = 1.4925 错误**。

### 2.3 「无法再加入更多部队」的阈值 = 133%
- 惩罚在 (Total-Battle)/Battle = 0.33 时触顶 → **Total = 1.33 × Battle**
- 超过后惩罚不再增长，新师不再进入（留在预备队）
- 日文站例：80 宽都市战最多投入 106（=132.5%）
- gamerempire 例：90 宽战场可放入 4 个 29 宽师（116 = 128.9% < 133%）

**正确阈值是 1.33（133%），不是 1/(1-0.33) ≈ 149.25%。**

### 2.4 惩罚作用于哪些属性
CW_meta.pdf（PDF 文本提取，空格丢失）：
> "...allunitsofthatsiderecieveapenaltyontheirsoftattack,hardattackandbreakthrough/defensedependingontheratioofusedcombatwidthtoavailablecombatwidth"

gamerempire：
> "the divisions will get debuffs to their Soft Attack, Hard Attack, and Defense based on how much you passed the Combat Width"

→ **软攻、硬攻、突破/防御**，整方所有参战师一起受罚。

界面修正名（游戏本体）：
```
BM_WIDTH: "Exceeding Combat Width"
BM_WIDTH_DESC: "The amount of divisions committed in a battle is above the possible width of the battle, which makes them fight less efficiently."
```

### 2.5 1.11 → 1.19.3 的公式变化
**1.11「Barbarossa」时期（CW_meta.pdf, Fabricensis, 2021-12-07, https://forumcontent.paradoxplaza.com/public/798717/CW_meta.pdf）逐字**：
> "Before patch 1.11 'Barbarossa' combat width in Hearts of Iron 4 used to be 80 with an additional 40 per additional attack direction."
> "If the division would not increase the used combat width over 1.2 times the available combat width, it reinforces the battle even if the used combat width now exceeds the available combat width"
> "If the division joining would put the used combat width over 1.2 times the available combat width, it cannot join and will stay in reserve until this changes"
> "Through careful testing I have determined that the penalty closely follows this formula: 150 × used combat width / available combat width - 150"
> "The maximum penalty at 20% over combat width is 30%."

→ 1.11：每 1% 超宽扣 **1.5%**，加入上限 **1.2 倍**，20% 超宽即 30% 惩罚。
→ 1.19.3：每 1% 超宽扣 **1%**，上限 **-33%**，加入上限 **1.33 倍**。
→ **公式确实在 1.11 之后被修改过**，但**无法确认是否恰好是 1.16 那一版**：本机 `game/changelog.txt` 首行即 `#### This file no longer hosts the patch notes ####`，只指向论坛。

## 4. 堆叠惩罚（stacking penalty）

### defines 原文（一手，行 1104-1106）
```lua
COMBAT_STACKING_START = 5,      -- at what nr of divisions stacking penalty starts
COMBAT_STACKING_EXTRA = 3,      -- extra stacking from directions
COMBAT_STACKING_PENALTY = -0.02,-- how much stackign penalty per division
```
（`stackign` 为官方源码中的拼写错误，逐字如此）

界面文本（游戏本体）：
```
BM_STACKING: "Stacking Penalty"
BM_STACKING_DESC: "Coordinating too many divisions is difficult."
```

### 对用户猜想的评估
猜想：阈值 = 5 + 3×(方向数-1)，超出阈值每师 -2%。

**评估：与 defines 注释方向一致，但未找到能确认该算法的权威原文。**
- `COMBAT_STACKING_EXTRA = 3` 注释 "extra stacking from directions" 最自然的读法是「每有额外方向带来的额外堆叠额度 = 3」，即阈值随方向数上升。
- 注释极简（6 个词），无法排除其他解释。
- 多次检索**未找到** HOI4 Wiki 上关于 stacking penalty 的逐字公式。

## 6. 侧翼 / flanking

### defines 原文（一手，行 1095）
```lua
FLANKED_PROVINCES_COUNT = 3,   -- Attacker has to attack from that many provinces for the attack to be considered as flanking
```
（与用户给出的英文逐字一致。）

### 从 3 个及以上省份进攻时攻方得到什么？
**未找到任何「攻方获得攻击加成」的证据。** 有据可查的多方向效果只有两项：

1. **加宽战场**（见第 3 节）
2. **削弱要塞效果**（游戏本体逐字）：
   - `BM_MULTIPLE_DIRECTIONS_DESC: "Attacking from many different directions will widen the combat width. If province is fortified it will reduce forts effect."`
   - `bunker_desc: "This building inflicts an attack penalty of $VALUE|+%0$ for each fort level on the attacker in combat. Attacking from multiple directions will reduce forts effect."`
   - `BM_FORT_MODIFIER_DESC: "...Attacking from several directions will reduce forts effect."`
   - 相关常数：`BASE_FORT_PENALTY = -0.15`（每级要塞 -15% 攻击惩罚）

### 关于「每增加一个进攻方向，攻方 +10% 攻击」
**判定：未找到任何支持证据，很可能是错误的民间传言。**
本机 defines、localisation、combat_tactics 中都没有「按方向数给攻方攻击加成」的字段。国策/学说中的 `multiple_attack_directions`（"Diversionary Attacks"）是**学说奖励、与方向数无关**：

```lua
multiple_attack_directions = {
    category_army = { breakthrough = 0.15 }
    fire_support  = { soft_attack = 0.1 }
}
```
（`common/doctrines/subdoctrines/land/operations_subdoctrines.txt` 行 321）

侧翼最可能的真实作用是**解锁特定战术**，例如 `tactic_encirclement`（`common/combat_tactics.txt` 行 187-220）：
```lua
tactic_encirclement = {
    is_attacker = yes
    trigger = {
        is_attacker = yes
        phase = no
        frontage_full = yes      # 前线已填满
        has_reserves = yes       # 尚有预备队
        OR = { skill_advantage > 0  has_trait = panzer_leader  has_trait = trickster }
    }
    combat_width = 0.5    #increased combat_width
    attacker = 0.25
    defender = 0.05
}
```
→ 触发要求「前线填满 + 有预备队」，效果为 **combat_width +50%、攻方 +25%**（战术加成，非「方向数 +10% 攻击」）。
